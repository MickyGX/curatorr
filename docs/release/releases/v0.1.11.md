# Curatorr v0.1.11

## Summary

- Fixed Lidarr artist tagging so Curatorr now applies its tags even when the artist already exists or the add path resolves to an already-monitored item.
- Added a Lidarr tag backfill path for existing Curatorr-managed artists and made unsupported album-tag behavior explicit on Lidarr builds that do not expose album tags.
- Fixed local-admin scoping so local Curatorr admins still see global listening stats while no longer generating or rendering fake personal discovery suggestions.
- Fixed Settings login tracking so Plex-auth logins populate the "Last Curatorr login" column and future Plex logins are written into the Curatorr login store.
- Improved history-page responsiveness by caching repeated artist and album artwork proxy requests and aligned the history and artists table headers with their content columns.

## Upgrade Notes

- Rebuild and redeploy Curatorr so the updated tagging, login tracking, history rendering, and table alignment changes are included in the running image.
- If you want to backfill Curatorr artist tags onto existing Lidarr-managed items, run `docker exec curatorr node /app/src/scripts/backfill-lidarr-tags.js` after deploying.
- On Lidarr servers that do not expose album tag support, the backfill only applies artist tags. Curatorr now logs album tagging as unsupported instead of silently pretending it worked.
- Hard refresh the browser after upgrade so the updated history and artists table assets replace older cached CSS and JavaScript.
