# Curatorr v0.1.35

## Summary

- **Smart playlist filter expansion** — Crescive and Curative now support cap-multiplier controls, live artist/track estimate previews, and richer exclusion rules for artist, album, and track names.
- **Folder-aware playlist filtering** — global playlists and smart-playlist types can now filter tracks by library folders and excluded libraries, with optional MusicBrainz recording deduplication to avoid duplicate releases.
- **Library path metadata capture** — Plex and Jellyfin library refresh now persist each track's source file path into `master_tracks`, enabling folder-based filtering and path browsing in Settings.
- **Container networking hardening** — Curatorr now sets Node DNS lookup order to `ipv4first`, reducing hostname resolution issues in environments where IPv6 answers cause upstream connection failures.

## Upgrade Notes

- No manual database migration is required. This release adds the `master_tracks.file_path` column automatically on startup.
- Rebuild and redeploy the container so the new smart-playlist controls, folder filters, and DNS behavior are included in the running image.
- Refresh the music library cache once after upgrading if folder browsers or path-based filters are empty, because file-path metadata is populated during master-track refresh.
- If Settings or Playlists still shows stale smart-playlist UI after upgrade, do one hard refresh so the browser picks up the updated CSS and JavaScript assets.
