# Curatorr v0.1.25

## Summary

- **Lidarr queue alias fix** — queued and follow-up Lidarr automation now resolves Plex users across shared username and email identities when they point at the same Plex server token. This fixes cases where requests could stay queued because the stored `user_plex_id` did not exactly match the role list entry.
- **Configured regular-user Lidarr access** — manual discovery and background Lidarr processing now follow the configured weekly quotas for the `user` role instead of being hard-blocked to admin, co-admin, and power-user accounts only. If you allow regular users `1 artist / 2 albums`, Curatorr now respects that setting end to end.
- **Clearer sidebar navigation** — the Artists sidebar entry now uses the music icon instead of sharing the same profile icon as Users.

## Upgrade Notes

- No database migrations required. Drop-in replacement for v0.1.24.
- If you already configured non-zero Lidarr quotas for regular users, rebuild and redeploy Curatorr to activate the access check and queue worker fixes.
- Existing queued Lidarr requests that were blocked by username/email identity mismatches can start processing after deploy, provided Lidarr is configured and the user still has quota available.
