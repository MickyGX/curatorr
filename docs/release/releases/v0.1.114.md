# Curatorr v0.1.114

## Summary

This release fixes Lidarr automation silently skipping the setup admin when their Curatorr username is the same as their Plex username. It also tidies the "What's new" pop-up so release highlights with nested bullets read as single items.

## Fixed

- **Lidarr auto-add skipped the setup admin.** Curatorr deliberately keeps the local setup account out of background automation, because it is an admin login rather than a listener. The check only compared usernames and emails, so when the setup admin also signed in through Plex with the same username, their Plex listening was treated as the setup account. Suggested artists were still generated and manual adds still worked, but auto-add never requested anything for that account and logged nothing about it.

  A setup admin name is now only excluded when it has never signed in through Plex. The same fix applies to the jobs that had the same check:
  - Lidarr auto-add
  - retrying failed or stuck Lidarr requests
  - suggestion rebuilds
  - Blend playlist syncs
- **"What's new" highlights split nested bullets.** When a release note bullet had sub-bullets or a follow-on paragraph, the pop-up showed each sub-bullet as its own highlight with no context. Sub-bullets and follow-on text are now joined into the highlight they belong to.

## Upgrade Notes

- Update the Curatorr app image and recreate the container as usual. The analyzer image is unchanged.
- No database or configuration changes.
- If you were affected by the Lidarr issue, auto-add picks up your suggested artists on the next **Lidarr: Review Due Artists** run (every 30 minutes by default). Your weekly automatic quota still applies. You can also run the job from **Settings → Jobs**.
