# Curatorr v0.1.43

## Summary

- **Analyzer image publishing fixed** — the release workflow now publishes `mickygx/curatorr-analyzer` alongside the main app image, so the sidecar is no longer omitted from Docker Hub releases.
- **x86_64 sidecar support restored** — the analyzer image now ships as a multi-arch manifest for both `linux/amd64` and `linux/arm64`, which brings analyzer sidecar mode back to standard x86_64 Docker hosts.
- **Safer Docker build caching** — app and analyzer image builds now use separate GitHub Actions cache scopes to avoid cross-image cache collisions during publish runs.

## Fixed

- Fixed the Docker publish workflow so it extracts tags and labels for both `mickygx/curatorr` and `mickygx/curatorr-analyzer`.
- Fixed analyzer-sidecar releases so the analyzer Dockerfile is built and pushed for both `linux/amd64` and `linux/arm64`.
- Fixed shared build-cache usage so the app and analyzer image jobs do not trample one another's GitHub Actions cache entries.

## Upgrade Notes

- If you rely on analyzer sidecar mode, upgrade to `v0.1.43` or later so `mickygx/curatorr-analyzer` is available on both ARM64 and AMD64 hosts.
- Existing `v0.1.41` and `v0.1.42` tags will not gain the missing analyzer image automatically; publish `v0.1.43` to get the corrected image set.
