# Curatorr v0.1.58

## Summary

- **Analyzer throttling controls added** — three new settings under Settings → Analyzer Throttling: chunk size (overrides the default 100/250 per mode), delay between chunks (ms), and delay between tracks (ms). All default to 0 (no change from previous behaviour). Designed for low-spec or shared NAS hardware where unthrottled analysis can saturate CPU or memory.
- **Built-in analyzer lowers its own CPU priority** — the analyzer script now calls `os.nice(10)` at startup so the OS schedules it at lower priority than interactive processes. No configuration required.
- **Per-track delay in sidecar mode** — when `analyzerTrackDelayMs` is set, the sidecar passes `--track-delay-ms` to the built-in analyzer script, inserting a sleep between each track. Useful for spinning-disk NAS where rapid sequential I/O causes audible seeks or thermal throttling.
- **Docker Compose resource limit examples added** — `docker-compose.yml` now includes commented-out `cpus` and `mem_limit` entries for the analyzer service so users who need hard caps can uncomment and adjust without researching the syntax.

## Fixed

- No bug fixes in this release.

## Added

- `analyzerChunkSize`, `analyzerChunkDelayMs`, `analyzerTrackDelayMs` config keys in `analysis` settings block. All normalised through `normalizeAnalysisSettings` with floor/clamp validation. Defaults: 0 (use built-in values, no added delays).
- Settings UI: "Analyzer Throttling" section beneath the existing analyzer mode fields with three numeric inputs and inline help text explaining each field.
- `clampNumber(options.chunkDelayMs, 0, 300000, 0)` and `clampNumber(options.trackDelayMs, 0, 5000, 0)` applied in `createTrackEnrichmentService`; `chunkDelayMs` fires a `setTimeout` between chunk iterations, `trackDelayMs` is forwarded to the sidecar payload as `trackDelayMs`.
- `--track-delay-ms` argument in `analyze-track-features.py`: sleeps `track_delay_ms / 1000` seconds between tracks (skipped after the last track). Validated with `max(0, args.track_delay_ms)`.
- `analyzer-sidecar.py` reads `trackDelayMs` from the POST payload (with int coercion and fallback to 0) and appends `--track-delay-ms <value>` to the subprocess command when non-zero.
- `os.nice(10)` call at analyzer startup (no-op on platforms that do not support it).
- `docker-compose.yml`: commented-out `cpus: "1.5"` and `mem_limit: 2g` examples on the analyzer service with explanatory comments.

## Upgrade Notes

- No configuration changes required — all new settings default to 0 (previous behaviour preserved).
- Recreate the app container after pulling `mickygx/curatorr:latest` and `mickygx/curatorr_analyzer:latest`.
- To enable throttling, open Settings → Analysis → Analyzer Throttling and set the values you want, then save.
