# Curatorr v0.1.69

## Summary

- **The app is much less likely to peg browser CPU or go unresponsive** because the Music Notes background now fully stops when it is disabled, pauses while the tab is hidden, and no longer keeps polling style state inside the animation loop.
- **Lidarr recovery is safer when upstream state drifts** so deleted Lidarr albums or artists no longer leave Curatorr stuck retrying dead IDs until the local database is reset.
- **Track inspection and Spotify import flows are more practical again** with richer track overview details, direct pin or unpin actions from the popup, and Spotify import narrowed back to owned playlists while restoring full imports for larger owned playlists.

## Fixed

- Fixed the Music Notes background animation so disabling it actually stops the render loop instead of continuing to repaint every frame.
- Paused the background effect when the tab is hidden and removed repeated settings/style reads from the frame loop, reducing unnecessary main-thread work on Chromium-based browsers.
- Added recovery handling for stale Lidarr album and artist references so Curatorr clears broken tracked-album state, resets dead artist links, and continues progression without requiring `curatorr.db` deletion.
- Updated the database helpers so `lidarr_artist_id` can be explicitly cleared when a stored Lidarr link becomes invalid.
- Added regression coverage for stale tracked Lidarr albums and missing Lidarr artists so these recovery paths stay protected.
- Expanded track overview popups with structured metadata, audio-profile, and library details instead of a single plain-text summary block.
- Added direct track pin and unpin actions from the overview popup so manual include state can be changed without navigating away first.
- Improved track-table actions layout so the extra controls fit cleanly without compressing the rest of the row.
- Restored full Spotify owned-playlist imports for larger playlists after the recent preview/import regression.
- Simplified the Spotify import modal back to owned playlists only, removing the confusing library and URL-import UI paths.

## Upgrade Notes

- Recreate the Curatorr container after pulling this release:
  `mickygx/curatorr:v0.1.69`
- Hard refresh the browser after upgrading. This release updates shared frontend assets for the overview popups, track actions, playlists page, and background animation behavior.
- If you previously had a Discover or Lidarr request stuck because the upstream Lidarr artist or album was deleted, retry it after upgrading before resorting to a database reset.
