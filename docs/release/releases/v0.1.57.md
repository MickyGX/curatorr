# Curatorr v0.1.57

## Summary

- **Root cause of slow startup and app sluggishness fixed** — every call to `pushLog` was synchronously writing and renaming a 239 KB file to NAS storage, blocking the Node.js event loop. During startup, jobs fire immediately and generate dozens of log entries in rapid succession, causing 30+ seconds of event-loop blockage before the server could start listening. Log persistence is now debounced: many rapid log entries are coalesced into one disk write per second instead of one per entry.

## Fixed

- `persistLogsToDisk` previously called `fs.writeFileSync` + `fs.renameSync` on every `pushLog` invocation. On QNAP NAS hardware, each synchronous write of the 239 KB `logs.json` file takes 50–100 ms. During startup with `runImmediately: true` job scheduling, this added up to 30+ seconds of blocking before `app.listen()` could complete, and continued to slow every request that triggered a log entry during normal operation. The function now debounces: it schedules a single write 1 second after the first queued entry and ignores further calls until that write completes.

## Upgrade Notes

- No app configuration changes are required.
- Recreate the app container after pulling `mickygx/curatorr:latest`.
- Startup should now be near-instant rather than 30+ seconds, and general page responsiveness will improve significantly.
