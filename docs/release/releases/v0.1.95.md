# Curatorr v0.1.95

## Summary

- **M3U playlist import.** Local `.m3u` and `.m3u8` files can be imported as managed custom playlists, matched against your library by file path first and by `Artist - Title` metadata second.
- **Imported playlists keep their source order.** Playlist tracks now carry the position they had in the source, so imported playlists no longer reshuffle on save.
- **Node 24 runtime.** The Docker image moves to `node:24-alpine` with `better-sqlite3` 12, which also unblocks CI.

## Added

- Added an **M3U** tab to the playlist import dialog, accepting `.m3u`/`.m3u8` files up to 2 MB and 5000 entries with a preview of matched, unmatched, and duplicate tracks before importing.
- Matched M3U entries against the master track cache by normalized file path (separator and URI-escape tolerant, with a unique-filename fallback), falling back to `#EXTINF` `Artist - Title` metadata through the existing text matcher.
- Treated `m3u-file` as a first-class import source across playlist conversion, imported-playlist settings, global playlists, and deletion. M3U imports are one-shot, so their sync period is fixed to disabled — there is no remote playlist to poll.

## Changed

- Added a `source_position` column to `playlist_tracks` and ordered playlist track reads by it, so imported playlists preserve their source ordering. Existing rows default to `0` and keep their previous ordering.
- Moved the runtime image from `node:20-alpine` to `node:24-alpine` and upgraded `better-sqlite3` from 11.x to 12.11.1.

## Fixed

- Fixed CI failing on every push: `node-version: "lts/*"` now resolves to Node 24, where `better-sqlite3` 11.x aborts at process teardown (`RemoveEnvironmentCleanupHook` assertion in `Statement::~Statement`). Five test files exited non-zero even though every assertion passed. CI is now pinned to the same Node major as the runtime image.

## Upgrade Notes

- No manual migration is required. The `source_position` column is added automatically at startup and backfills to `0`, which preserves existing playlist ordering.
- The container now runs Node 24. `better-sqlite3` is compiled during the image build as before and the SQLite database file format is unchanged, so existing `data/` volumes are used as-is.
- Rebuild or redeploy Curatorr to pick up the new runtime and the M3U import.
