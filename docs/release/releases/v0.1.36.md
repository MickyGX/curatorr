# Curatorr v0.1.36

## Summary

- **ListenBrainz sync hardening** — ListenBrainz playlist imports now emit clearer failure logs and add a request fallback path for container environments where Node `fetch` fails even though direct CLI requests succeed.
- **Jellyfin settings and webhook polish** — the Settings UI now gives Jellyfin its own connection panel, library selection flow, and webhook registration helpers so ongoing administration is less manual.
- **Smart-playlist admin controls** — Settings continues the smart-playlist expansion with richer exclusion rule handling, folder-aware playlist filters, cap controls, and live preview tooling across Curatorr and global playlist builders.
- **Lidarr and media-server quality fixes** — the release bundles the latest Lidarr automation refinements, media-server metadata handling updates, and settings-page cleanup from the current development branch.

## Upgrade Notes

- No manual database migration is required for this release.
- Rebuild and redeploy the container so the ListenBrainz fallback path, Jellyfin settings updates, and smart-playlist tooling changes are included in the running image.
- If ListenBrainz sync still fails after upgrade, check the Curatorr log view under the `ListenBrainz` filter first. This release adds more explicit fetch-failure logging for the initial playlist discovery step.
- If Settings still shows stale smart-playlist or Jellyfin UI after upgrade, do one hard refresh so the browser picks up the updated CSS and JavaScript assets.
