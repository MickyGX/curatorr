# Curatorr v0.1.104

## Summary

This release adds a play count filter to smart playlists, so playlists can include or exclude tracks based on how often a listener has played them.

## Added

- **Play count filter**: **Create smart playlist → Content filters → Play count** has **At least** and **At most** fields. Leave either blank for no limit. Setting **At most** to `0` keeps only tracks the listener has never played.
- Play counts come from each listener's Curatorr play history, the same counts used by the **Play count** sort. Plays from before Curatorr was set up count only if they were backfilled from Tautulli or Last.fm.
- The filter works with the existing rules. For example, **At least 10** plays + **Not played within last 120 days** + sort by **Play count** + a 50-track cap builds a "Repeat Rewind" playlist of old favourites, with Curatorr's duplicate handling ([#175](https://github.com/MickyGX/curatorr/discussions/175)).
- The rule applies to playlist builds, the wizard preview, blended playlists, and admin global playlists, and is shown on the wizard's review step.

## Fixed

- No fixes in this release. Added regression tests for minimum, maximum, and combined play count and last-played filtering.

## Upgrade Notes

- Update the Curatorr app image and recreate the container as usual. No database migration or analyzer update is required.
- Existing playlists are unchanged. The filter is off until you set a value.
