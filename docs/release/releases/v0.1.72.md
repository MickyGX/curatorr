# v0.1.72 — Artist Pipeline Scoring Overhaul & Spotify Public Import

**Released:** 2026-04-14

## Summary

A significant overhaul of the Artist Pipeline recommendation engine, fixing scoring fairness between library-affinity and Last.fm similar artists, adding pipeline actions (Browse albums, Curatorr pick), configurable discovery settings, and a scheduled rebuild job. Also includes a Spotify public-page import fallback so shared playlists can be imported without an OAuth connection.

## Fixed

- **Genre affinity taxonomy mismatch** — `buildGenreAffinity` now expands compound catalog genres into sub-tokens (e.g. `Pop/Rock` adds `pop` and `rock` individually at 75% weight). Last.fm tags like `rock`, `pop`, `folk` now correctly match catalog-derived affinity scores, resolving the root cause of Last.fm artists clustering at the bottom of the pipeline.
- **Perpetual stale-rebuild loop** — the model version check was comparing against the old hardcoded constant `phase2d-lastfm-mixed-pool` rather than the current model version. This made every artist appear stale on every page load, triggering a rebuild that could never settle. The constant is now exported and the check uses it directly.
- **Stale suggested entries never refreshed** — `replaceSuggestions` only refreshed scores for actioned (non-suggested) artists from the full scored pool. Stale `suggested` entries outside the top-N display slot kept their old scores from previous algorithm versions indefinitely. The refresh now covers all non-dismissed entries in the pool.
- **Inflated legacy scores** — 152 rows with pre-model-versioning scores (200–330 range, impossible under the current formula) were reset to 0. Ongoing: actioned artists not re-evaluated in a rebuild also have their scores zeroed to prevent drift.
- **Score column showing stale numbers** — actioned artists (in_progress, added_to_lidarr etc.) now show `—` when their score is 0 rather than a meaningless historical figure.
- **Pipeline ordering** — the pipeline now sorts by status priority (stuck → in_progress → queued → in_library → suggested → added_to_lidarr → dismissed) before score, so actionable items surface first rather than being buried by high-scoring legacy entries.
- **"Already in Lidarr" noise** — the 96 legacy `already_in_lidarr` entries are excluded from pipeline display; the Lidarr progress table is authoritative for those artists.
- **"Browse albums" showing no artist card** — clicking Browse albums now injects a synthetic artist card into the search viewport so the user always knows which artist's albums are being displayed.
- **Artists disappearing from pipeline after Curatorr pick** — `added_to_lidarr` entries were being excluded from the pipeline query, causing artists to vanish immediately after being actioned. They are now retained at the bottom of the queue.
- **Spotify URL import requiring OAuth** — import now falls back to the public-page scraper when no Spotify connection is active, allowing shared playlist URLs to be imported without OAuth.

## New

- **"Browse albums" pipeline action** — opens the Manual Discovery section pre-populated with the pipeline artist's name and a synthetic artist card, ready to browse and select an album for Lidarr.
- **"Curatorr pick" pipeline action** — with a confirmation prompt, automatically selects the highest-ranked starter album and submits it to Lidarr without requiring manual album selection.
- **Discovery sensitivity setting** — a 1–5 slider in Discovery settings controls the minimum Last.fm similarity score needed to surface an artist (1 = very broad, 5 = close matches only).
- **Minimum role gate** — a role dropdown in Discovery settings restricts the Last.fm similar artist pool to specific user roles (admin, co-admin, power user, user, or disabled).
- **Scheduled Artist Pipeline Rebuild job** — rebuilds artist, album, and track suggestions for all users on a configurable schedule (default: every 6 hours). Can also be triggered manually from the Jobs settings page.
- **Last.fm source icon** — the Last.fm favicon now appears inline with the artist name rather than on a separate line beneath it.

## Upgrade Notes

- On first page load after upgrade the pipeline will trigger a full rebuild for each user. This clears the stale model version entries and refreshes all scores. For large libraries this may take 10–30 seconds per user.
- Legacy `already_in_lidarr` entries remain in the database but are no longer shown in the pipeline. No data is deleted.
- The 152 rows with inflated scores have been reset to 0 in-place via a one-time migration that ran at deploy time.
