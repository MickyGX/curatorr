# Curatorr v0.1.111

## Summary

This release fixes two bugs: the built-in analyzer skipping every `.m4a` track, and TIDAL mix links failing to import.

## Fixed

- **Analyzer skips `.m4a` (AAC/ALAC) tracks** ([#193](https://github.com/MickyGX/curatorr/issues/193)). Analyzer images built recently ship librosa 1.0, which removed its fallback decoder, so files libsndfile cannot open were logged as `skipping unreadable track ... Format not recognised` and never got BPM, key, energy or danceability. When librosa cannot open a file, the analyzer now decodes it with the ffmpeg already in the image, at the same sample rate and with the same duration cap. Channels are averaged the same way librosa does, so energy values match the librosa path. A decode that hangs is stopped after 5 minutes, and a file ffmpeg cannot read is still skipped with the original message.
- **TIDAL mix import fails at preview** ([#180](https://github.com/MickyGX/curatorr/issues/180)). Pasting a `tidal.com/mix/...` link into the URL tab of the import dialog always failed with "Enter a valid TIDAL playlist or mix URL, or a playlist id." The dialog sent the server the bare mix id, which the server only accepts as part of a mix link. The dialog now sends the link, so mixes preview and import. TIDAL mix import is still experimental: which kinds of mix TIDAL's API returns is not yet confirmed, and a mix it does not return shows a "did not return this mix" message.
- Added regression tests for the ffmpeg decode arguments, the duration cap, the channel averaging, and for every TIDAL link the import dialog accepts being accepted by the server.
- Thanks to @JesusMacabee and @Tubeman-cell for the reports, root-cause analysis and testing.

## Upgrade Notes

- Update both the Curatorr app image and the analyzer image (`mickygx/curatorr-analyzer`), then recreate the containers as usual. The `.m4a` fix is in the analyzer image; the TIDAL fix is in the app image.
- No database changes. `.m4a` tracks that were skipped have no features saved, so they are analyzed on the next analyzer run. No manual re-run or reset is needed.
- If you build the analyzer image yourself, rebuild it from `docker/analyzer/Dockerfile`.
