# Curatorr v0.1.15

## Summary

- Added Last.fm History Sync — a new background job that fetches recent scrobbles from Last.fm for each user who has configured a Last.fm username and backfills plays not already recorded in Curatorr. Requires a Last.fm API key (set in Discovery settings) and a username saved in User Profile.
- Added Last.fm username field to User Profile settings so each user can connect their own Last.fm account independently.
- Fixed Plex server owner not appearing in the Settings → Users → Plex Users table. The Plex API (`plex.tv/api/users`) intentionally excludes the account that owns the server; the owner is now fetched separately and injected at the top of the list, locked as admin.
- Fixed Plex server owner being assigned the wrong role (Normal User) after login when `admins.json` did not contain their identifier. `resolveRole` now checks `config.plex.adminUser` as a fallback and auto-promotes the owner, writing their identifier into `admins.json` so future logins resolve correctly without re-reading config.

## Upgrade Notes

- Rebuild and redeploy Curatorr so the Last.fm sync job and Plex owner fixes are included in the running image.
- The Last.fm History Sync job is **disabled by default**. Enable it in Settings → Jobs once you have a Last.fm API key configured in Discovery settings and at least one user has saved their Last.fm username in User Profile.
- If your Plex server owner has been appearing as a normal user, go to Settings → Plex (the Plex tab, not Users) and ensure the **Plex Admin User** field contains their Plex username or email address. On next login via Plex SSO they will be automatically promoted to admin.
- No database schema migration is required beyond the automatic column additions handled at startup (`lastfm_username`, `lastfm_api_key`, `lastfm_sync_watermark`).
