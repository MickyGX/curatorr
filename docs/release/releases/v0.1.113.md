# Curatorr v0.1.113

## Summary

This release fixes the Playlists page loading very slowly, or timing out, on large libraries. The playlist builder's filter lists are now built in the background and reused, instead of being rebuilt from the whole library on every visit. Settings → Global Playlists loads faster for the same reason. A slow Plex server also no longer holds up the page while it fetches playlist artwork.

## Fixed

- **Playlists page slow on large libraries.** Every visit to the Playlists page rebuilt the builder's filter lists from the whole library:
  - genres, moods and artist countries
  - album genres, styles and moods
  - Last.fm tags and decades
  - the folder browser
  - which feature presets have enough analysed tracks

  Each list meant reading every track. On a library of about 530,000 tracks the page took over a minute and timed out in the browser. The lists are now built in a background thread that doesn't hold up the rest of Curatorr, and are reused until the library changes. Settings → Global Playlists shares the same lists.
- **Slow Plex held up playlist artwork.** The Playlists page, the dashboard and the Blend carousel wait for Plex to list your playlists so they can show their artwork. That request had no time limit. It now gives up after 8 seconds and shows the fallback artwork instead.
- **Removed libraries could linger in cached track lists.** Deselecting a Plex library in Settings removed its tracks from the database, but an in-memory copy of the track list could keep serving them until a restart. That copy is now cleared when tracks are removed.

## How the lists stay up to date

- The lists are rebuilt after a library sync, track enrichment, an analyzer run or a Last.fm tag update.
- When a page needs fresh lists, it waits up to 1.5 seconds for the rebuild. Most libraries finish well within that, so you always see current lists.
- On very large libraries the rebuild takes longer. The page shows the previous lists straight away and picks up the new ones on a later visit. To keep the server from rebuilding constantly while a long job runs, Curatorr waits a while between rebuilds, never more than 5 minutes.
- The lists are kept in memory and start building as soon as Curatorr starts. If you open the Playlists page or Global Playlists on a very large library before the first build finishes, the filter lists are empty and a notice asks you to reload in a few minutes.

## Upgrade Notes

- Update the Curatorr app image and recreate the container as usual. The analyzer image is unchanged.
- No database or configuration changes.
- Very large libraries only: straight after an upgrade or restart, the Playlists page may briefly show the "lists are still being built" notice. Reload after a few minutes.
