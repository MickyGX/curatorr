# Curatorr v0.1.78

## Summary

- **Lidarr artist progression no longer gets stuck after a confirmed download** because Curatorr now lets `downloaded` recovery continue into the catalog expansion and completion checks.
- **Artists can reach `catalog_complete` properly after Lidarr import finishes**, instead of remaining stranded in intermediate progression stages.
- **Media-server-only downloaded matches still return early** so Curatorr does not advance catalog state before Lidarr has actually imported the files.

## Fixed

- Fixed the artist acquisition recovery flow so a `downloaded` result from Lidarr no longer returns early before the later catalog expansion logic runs.
- Restored progression from post-download recovery into catalog expansion and `catalog_complete` state updates.
- Prevented artists from remaining stuck in intermediate stages such as `catalog_expanded` when Lidarr had already confirmed the album was downloaded.
- Preserved the early-return behavior for `downloaded_media_server*` states, which still need to wait for Lidarr import before catalog expansion should run.
- Tightened the recovery branching so only true non-download recovery states short-circuit the remainder of the progression flow.
- Improved reliability of the end-to-end Lidarr acquisition lifecycle without requiring manual cleanup or retriggering of stuck artists.

## Upgrade Notes

- No manual migration is required for this release.
- Artists already waiting in post-download progression should move forward the next time Curatorr reviews them.
- If you have artists that appeared stuck after Lidarr download confirmation, retrying or waiting for the next review cycle after upgrade should let them complete normally.
