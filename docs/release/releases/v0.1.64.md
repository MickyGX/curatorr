# Curatorr v0.1.64

## Summary

- **Discover request tracking is now album-aware** — Curatorr no longer treats artist-level library presence as proof that a requested album was acquired. Discover and Lidarr progression now reconcile against album titles, support close edition matches such as standard vs deluxe, and can also promote completed requests from live Lidarr download state when the local cache has not updated yet.
- **Discover queue management is much more usable** — the Queue now contains everything not truly available yet, Added For You only shows completed in-library results, and queue rows now expose a compact action menu for retrying failures, deleting requests, or manually marking a stuck request as available.
- **Failed and edge-case request flows degrade more cleanly** — failed Curatorr-pick overview popups now return a clear unavailable state instead of a server error, release/quick-start popups scroll correctly again, and the Discover queue menu now repositions within the scroller instead of being clipped.

## Fixed

- Replaced artist-level Discover request reconciliation with album-level matching in both page rendering and API responses, including variant-aware matching and manual availability overrides.
- Added a shared Lidarr/download promotion step so completed requests can move out of the queue when Lidarr shows the tracked album has files, even before `master_tracks` catches up.
- Updated Lidarr artist progression recovery to use album-level local-media reconciliation instead of broad artist-track presence, which addresses the repeated `queued` / `started` search loop behind issue `#27`.
- Added Discover request actions for delete and mark-available, and moved retry handling into a row action menu rather than a single inline button.
- Fixed failed Curatorr-pick overview requests so they now show a neutral `Selection unavailable` modal instead of a Lidarr server error.
- Fixed Discover queue/history bucketing so `Added For You` only shows requests that are actually completed and available in the library, while unresolved `completed`, `failed`, `queued`, and `processing` items stay in the Queue.
- Fixed release and quick-start popups so their body content scrolls again when the content exceeds the available modal height.
- Tightened the Discover queue action column, centered the menu trigger, made the menu flip upward when needed inside the scroll area, and hid the drag handle on touch devices where queue reordering is not currently usable.

## Upgrade Notes

- Recreate the app container after pulling `mickygx/curatorr:latest`.
- Hard refresh the browser after upgrading. This release changes Discover queue behavior, popup scrolling, and shared CSS, so cached assets can leave the old interaction model in place.
- Requests manually marked as available now count as completed Discover history items and also advance the linked Lidarr progress row to `album_acquired`.
- If a request still stays in the Queue after upgrade, the most likely remaining cause is stale local library metadata rather than the old artist-level reconciliation bug.
