# Curatorr v0.1.53

## Summary

- **Windows desktop startup crash fixed** — users upgrading from older versions no longer hit a fatal `SqliteError: no such column` crash on launch caused by partial indexes referencing columns that didn't yet exist in their database.
- **Dashboard stats fixed** — excluded track count, skip-tier artists, belter tracks, and heard tracks on the dashboard now correctly reflect the logged-in user rather than the suggestion user.

## Fixed

- Moved partial indexes on `master_tracks.recording_mbid`, `track_enrichment.recording_mbid`, and `play_events.session_key` out of the static schema and into the migrations block, so they are created only after the corresponding columns are confirmed to exist on upgrade.
- Fixed dashboard route using `suggestionUserId` instead of `userPlexId` for four stat queries, which caused incorrect counts to display for users whose suggestion user differed from their logged-in identity.

## Upgrade Notes

- No app configuration changes are required.
- Recreate the app container after pulling `mickygx/curatorr:latest`.
- Windows desktop users affected by the startup crash should install the updated `curatorr-desktop` release.
