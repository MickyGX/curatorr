# Curatorr v0.1.94

## Summary

- **Plex playlist sync verification.** Curatorr now reads generated Plex playlists back after replacing their contents, stores the confirmed landed count, and warns when Plex accepts a request but drops stale rating keys.
- **Cleaner master-track refreshes.** Successful master refreshes now prune stale cached tracks from the selected libraries so dead Plex keys stop feeding future smart playlist builds.
- **Playlist and Lidarr polish.** Artist-country playlist wizard selections are preserved correctly, and Lidarr artist-add payloads now keep unsupported monitoring values out of `monitorNewItems`.

## Fixed

- Verified Plex generated-playlist writes by comparing requested rating keys with the playlist items that actually land after sync.
- Stored confirmed generated-playlist counts and missing-track counts after Plex sync, including warning logs and playlist sync history for dropped keys.
- Pruned stale `master_tracks` rows, related enrichment rows, and playlist-track rows for refreshed libraries after a successful master refresh.
- Preserved `artist-countries` selections when navigating through the smart playlist wizard.
- Sent only Lidarr-supported `monitorNewItems` values for new artists: `all`, `new`, or `none`, while keeping the wider `addOptions.monitor` mode for `existing`, `latest`, and `first`.
- Added focused regression tests for Plex partial playlist writes, master-track pruning, and Lidarr monitoring payload handling.

## Upgrade Notes

- No manual migration is required.
- After upgrading, run or wait for a Master Track Cache Refresh so stale Plex keys can be pruned from refreshed libraries.
- Rebuild or redeploy Curatorr so the playlist sync verification and Lidarr payload fixes are active in the running container.
