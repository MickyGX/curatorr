# Curatorr v0.1.102

## Summary

This release fixes Plex playlist rebuilds that fail when cached music IDs no longer refer to tracks, including after a Plex database repair. It also makes cache refresh failures visible and prevents incomplete Plex scans from triggering stale-entry cleanup.

## Fixed

- Plex playlist rebuilds now split batches rejected with HTTP 400 to isolate problematic items. Items are skipped only when Plex confirms they are missing or no longer refer to a track; authentication and other server errors still surface.
- Valid tracks retain their order, and missing-item counts include tracks skipped during recovery, even if final playlist verification is unavailable.
- Recovery from a changed Plex server identifier retries the rejected batch without clearing previously added tracks again.
- Legacy smart playlist rebuilds now use the same recovery and verification path as generated playlists, check playlist-clear failures, and record the confirmed track count when verification succeeds.
- Master Track Cache Refresh now propagates failures to Jobs and the manual refresh API instead of returning zero and being marked successful. Missing server configuration or music-library selection also produces an error.
- Plex track scans now reject failed HTTP responses, invalid track counts, and unexpectedly empty pages before stale-entry cleanup can run. Each track-page request has a 60-second timeout.
- Added regression tests for reassigned music IDs, rejected playlist batches, error reporting, incomplete scans, and removal of obsolete cache entries after a complete refresh.

## Upgrade Notes

- Update the Curatorr app image and recreate the container as usual. No database migration, configuration changes, or analyzer update is required.
- If playlists failed after a Plex database repair or library rebuild, run **Jobs → Master Track Cache Refresh**, confirm that it succeeds, then rebuild the affected playlists.
- A failed refresh now shows an error. Resolve the reported server, connection, or configuration problem before retrying; an incomplete scan preserves existing cache entries instead of pruning them.
- Playlist recovery can skip unavailable tracks but does not repair the Plex database or remap song identities. A successful cache refresh is still needed to remove obsolete IDs and load current tracks.
