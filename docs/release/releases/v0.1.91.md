# Curatorr v0.1.91

## Summary

- **Folder browser now lists your whole library.** The smart playlist wizard Step 4 "Include/Exclude folders" browser (and the global-playlist folder browser under Settings) used to build its list from only the first 2000 tracks, so large one-folder-per-artist libraries stopped partway through the alphabet and hid every later artist. Folders are now derived from distinct directories in SQL, so the complete folder tree is available no matter how many tracks you have.
- **The Lidarr retry job no longer wedges on duplicate failures.** "Lidarr: Retry Failed Requests" could permanently break once duplicate `failed` rows piled up for the same artist/album (for example during a long Lidarr outage): re-queueing the second duplicate hit a `UNIQUE constraint` error that aborted the entire job. The job is now dedup-aware and constraint-safe.
- **Duplicate failed requests stop accumulating.** Enqueuing a request now revives an existing failed row for the same artist/album instead of adding another, so the pile-up that caused the wedge cannot build in the first place.

## Fixed

- Step 4 folder browser and the Settings global-playlist folder browser now list every folder in large libraries instead of truncating at ~2000 tracks worth of paths. Directory extraction is done in SQL so the work scales with folder count, not track count, and does not scan every track path on page render.
- The `lidarrRetryFailed` scheduled job groups failed requests per artist/album, collapses redundant duplicates, and re-queues at most one per artist/album under the retry limit. Each item is isolated so a single `UNIQUE constraint` collision can no longer abort the whole job.
- The stuck-`processing` reset path in the retry job drains a duplicate on collision instead of throwing.
- `enqueueLidarrRequest` now deduplicates against `failed` rows: it revives the most recent failed row for an artist/album and drains older duplicates rather than inserting a new row.

## Upgrade Notes

- No database migration required.
- No environment variable changes required.
- If your Lidarr retry job was already wedged with duplicate failed rows, the accumulated duplicates are collapsed automatically on the next **Lidarr: Retry Failed Requests** run — no manual database cleanup needed.
- After upgrading, open the smart playlist wizard **Step 4 -> Include folders** (or **Settings -> global playlist folders**) and confirm the full folder list is now shown.
