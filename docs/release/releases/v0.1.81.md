# Curatorr v0.1.81

## Summary

- **Overview and Report are now the primary analytics destinations** with dedicated sidebar entries, Overview as the default post-login landing page, the old Dashboard removed from normal navigation, and the admin "Viewing" strip available on both pages.
- **The analytics pages received a broad refinement pass**: Overview now has dropdown period pickers, richer clickable artist/album/track cards, Top Playlists, and cleaner heatmap styling, while Listening Report adds a featured top-track module, a 52-week activity heatmap, tighter chart layouts, and more polished period controls.
- **Auth, automation, and import flows are more reliable** with server-side Plex Home selection state, better avatar fallbacks, smart-playlist last-played filters, configurable Lidarr defaults for new artists, and stronger Spotify playlist import behavior for both owned-playlist and public-URL workflows.

## Fixed

- Moved root, login, setup, wizard, popup-login, and PWA start defaults from `/dashboard` to `/overview`, while keeping `/dashboard` available only as a direct URL for legacy access.
- Added the shared admin preview/viewing strip to both Overview and Report so local administrators can switch user context there just like Discover, History, Artists, and Playlists.
- Reworked Overview to expose popup-driven artist/album/track cards, dropdown period selectors, Top Playlists, refreshed header icons, and a more flexible heatmap layout.
- Expanded Listening Report with a featured top-track panel, 52-week activity heatmap, revised period labels, stronger chart spacing, and better hover/tooltip affordances for the clock, tier, ratio, and fingerprint visuals.
- Centralized server-side date formatting helpers so dashboard/report activity labels, heatmaps, streaks, and tag-stream labels respect the configured server time zone more consistently.
- Added `tzdata` to the container image, enabled `TZ` by default in `docker-compose.yml`, and surfaced the server time zone in Settings so log and analytics timestamps align with the deployment configuration.
- Stored pending Plex Home selection state server-side instead of stuffing it into the session cookie, reducing stale-cookie conflicts during popup auth and hardening the home-user selection flow.
- Normalized Plex Home `protected` and `admin` flags across boolean and string payloads, so protected home users and protected home owners route to PIN entry correctly.
- Added public/proxied avatar fallback handling for Plex Home selection and PIN pages, including metadata lookup fallback when Plex omits home-user thumbs in the initial response.
- Added smart-playlist `Last played` rules across wizard state, preview/build parsing, and scoring maps, so playlists can now target tracks played within a window, not played within a window, or never played.
- Added Lidarr automation defaults for new artists: configurable quality profile, metadata profile, and monitoring mode, with Settings page profile loading and validation against live Lidarr profiles.
- Fixed connected Spotify playlist imports to follow API pagination beyond the second page, restoring reliable large-playlist imports for owned playlists.
- Forced Spotify URL-tab imports down the public-source path even for users with connected accounts, so the UI no longer silently mixes authenticated owned-playlist imports with public-page URL imports.
- Clarified the README and integrations docs so users understand that owned Spotify playlists are the reliable import path and public/shared URL imports remain limited by what Spotify exposes publicly.

## Upgrade Notes

- No manual migration is required for this release.
- If you want server-rendered analytics, heatmaps, and logs to use local time, set `TZ` for the Curatorr container. This release now respects it more consistently.
- If you use Lidarr automation, review the new default quality profile, metadata profile, and monitoring mode settings after upgrading. Leaving them unset preserves the existing Lidarr-default behavior.
- For large Spotify imports, prefer the connected-account Spotify tab with playlists owned by that Spotify account. Public/shared URL imports still depend on Spotify's public web output and may expose only part of a playlist.
