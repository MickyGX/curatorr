# Curatorr v0.1.108

## Summary

This release makes the Overview, Discover, History and Report pages much faster on large libraries. Results are unchanged. Thanks to @quinneydavid for the contribution.

## Fixed

- **Slow pages on large libraries**: three queries scanned the whole library on every page load. Because database queries run one at a time, every other request, even a simple version check, waited behind them. On a library of about 385,000 tracks:
  - Discover: about 6 seconds to under 0.1 seconds.
  - History: about 2.2 seconds to about 0.2 seconds.
  - Overview: about 5.7 seconds to about 1 second.
  - Report: about 4.6 seconds to about 2.7 seconds.
- **Album popularity ranks** (Overview, History and track views) now rank only the albums of the tracks being shown, instead of every album in the library.
- **Album matching on Discover** now uses an index for case-insensitive artist and album lookups instead of scanning the library for each album.
- **Top playlists** (Overview and Report) now start from the listener's plays and look up their playlists through a new index.
- Results were checked against the previous queries and are identical. ([#183](https://github.com/MickyGX/curatorr/pull/183))

## Upgrade Notes

- Update the Curatorr app image and recreate the container as usual. No analyzer update is required.
- Two database indexes are created automatically on the first start. On a very large database this can take several seconds, once. Later starts are unaffected.
