# Curatorr v0.1.60

## Summary

- **Popularity-based smart playlists are now first-class** — the wizard now exposes both album-level popularity filtering and absolute popularity filtering using the Plex `ratingCount` data Curatorr already stores. This makes it possible to build playlists from the most popular tracks in a genre, artist pool, or broader filtered candidate set without guessing raw numeric thresholds.
- **Popularity is now visible across the app** — a flame badge now marks the top 3 tracks on each album by Plex `ratingCount`, and that indicator is rendered consistently across playlist tracks, the Tracks page, Dashboard summaries, History, and Blend results.
- **The playlist wizard is more stable and easier to use** — popularity decisions were moved into the main Step 3 output-rules flow, the advanced Step 4 cleanup screen was simplified back to text/file-path rules, dropdown headings were corrected, and the modal frame now keeps a fixed size while only the body scrolls between steps.

## Fixed

- Smart-playlist track rules now support typed Plex `ratingCount` comparisons in the shared rule engine, while the main wizard exposes higher-level popularity controls instead of forcing users to reverse-engineer raw rating-count values.
- Playlist previews and actual playlist builds now use the same popularity logic, so preview counts match the saved playlist behaviour for album Top 3 filtering and absolute popularity slices.
- Popularity metadata is now attached to dashboard top tracks, recent history rows, playlist track loads, tracks-page rows, and blend top tracks, ensuring the flame badge survives both initial server render and follow-up API fetches.
- The Step 4 advanced-rule editor no longer breaks when fields change, and the field/match/value labels now render in the intended stacked layout above each control.
- The smart-playlist wizard modal no longer jumps in height between sparse and dense steps; the dialog frame stays fixed while the inner body scrolls.

## Upgrade Notes

- Recreate the app container after pulling `mickygx/curatorr:latest`.
- Absolute popularity controls currently rely on Plex `ratingCount`. On Jellyfin and Emby libraries there is no equivalent track-popularity source yet, so those filters will not provide meaningful results there.
- Older saved templates or playlists that carried a legacy Step 4 `ratingCount` cleanup rule will now drop that advanced-rule row in the wizard; use the Step 3 popularity controls instead.
