# Curatorr v0.1.37

## Summary

- **ARM64 support** — the Docker image is now multi-arch (`linux/amd64` + `linux/arm64`), so Raspberry Pi and Apple Silicon NAS devices can run Curatorr natively without emulation.
- **Admin preview fixes** — viewing another user as admin now shows correct playlists, play history, and artwork; a dual-identity system separates the webhook play ID from the OAuth login ID so each query uses the right key.
- **Duplicate track fix** — Crescive and Curative playlists no longer include the same song multiple times when it exists across different albums; deduplication is by normalised artist and title, including featured-artist variants like `f/` and `feat.`.
- **Personal playlist sync** — user-created smart playlists are now included in the scheduled sync job alongside Crescive, Curative, and Daily Mix.

## Fixed

- Admin preview showing no playlists or play history when a user's Plex webhook identity differs from their OAuth login identity.
- Playlist artwork not loading in admin preview — the previewed user's own Plex token is now used instead of the admin token.
- Dashboard playlists panel showing empty when viewing another user in admin preview.
- Duplicate and triplicate tracks in Crescive and Curative playlists caused by the same song appearing across multiple albums.
- Featured-artist name variants (e.g. `Eminem f/ Eye-Kyu`) being treated as a different artist from `Eminem` during deduplication.
- User-created smart playlists not rebuilt by the scheduled sync job.

## Upgrade Notes

- No manual database migration is required for this release.
- ARM64 users can now pull the standard `mickygx/curatorr:latest` image directly — no separate image or build step needed.
- After upgrading, trigger a manual Smart Playlist Sync from the Playlists page to apply the duplicate-track fix immediately rather than waiting for the next scheduled run.
