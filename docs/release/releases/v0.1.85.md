# Curatorr v0.1.85

## Summary

- **Lidarr automation no longer loops on unobtainable albums.** Albums that can never be acquired (no indexer release available, or a grab that Lidarr never imports) are now given a finite retry budget. Once exhausted, they are marked `unobtainable`, catalog expansion skips ahead to the next album, and the daily re-search loop stops.
- **Playlist sync auto-recovers from a stale Plex machineId.** When Plex returns HTTP 400 during a playlist write, Curatorr now re-fetches the machine identifier and retries the operation automatically, saving the refreshed ID for future syncs.
- **Setup-admin startup cleanup is now opt-in.** The aggressive purge of setup-admin music data no longer runs automatically on startup, removing the risk of data loss when a media-server user ID overlaps with the setup-admin identity.
- **getMasterTracks is faster for large libraries.** A per-db WeakMap cache means the full `master_tracks × track_enrichment` scan runs once per data change rather than on every smart playlist build call.

## Fixed

- Lidarr `catalog_expanded` artists with a `last_manual_search_status` of `queued` or `started` stuck for more than 7 days are now automatically marked `unobtainable` on startup and deferred by one week, clearing the loop without requiring manual intervention.
- The Lidarr fallback release-grab path now counts failed grab attempts (`manualGrabAttempts`) and terminates expansion search after 3 empty fallbacks, after 14 days stuck with no library import, or after 2 empty fallbacks when the artist already has a library presence.
- Acquisition counters (`searchAttempts`, `monitorRepairCount`, `manualGrabAttempts`) are now reset when catalog expansion moves to a new album, so each album gets its own independent retry budget.
- The Lidarr in-progress command status is now persisted as the live Lidarr value rather than the value frozen at the time the command was triggered, keeping the stored field accurate across reconcile cycles.
- Playlist sync now re-fetches the Plex machineId on HTTP 400 and retries with the refreshed identifier, saving it to config for subsequent syncs. User tokens are also passed as a fallback when resolving the machineId so personal Plex server tokens work correctly.
- Playlist sync error messages now include the HTTP response body (capped to 200 characters) to make failures easier to diagnose.
- `rebuildSmartPlaylist` now logs a warning and stops adding items when an individual batch request fails, rather than silently continuing with partial results.
- `cleanupSetupAdminMusicState` is now disabled by default to prevent data loss when media-server user IDs collide with the setup-admin identity. Enable with the `CURATORR_ENABLE_SETUP_ADMIN_MUSIC_CLEANUP=true` environment variable or `maintenance.enableSetupAdminMusicCleanup: true` in the Curatorr config.
- Added an in-process WeakMap cache for `getMasterTracks` that returns a cached result on repeated calls within the same data generation, with automatic invalidation on any write to `master_tracks` or `track_enrichment`.
- Added regression test for the unobtainable album scenario — confirms one release lookup, skips to the next catalog album, and resets acquisition counters on the freshly expanded album.
- Updated setup-admin cleanup tests to reflect the new opt-in behaviour.

## Upgrade Notes

- No manual database migration is required. Existing installs with artists stuck in `catalog_expanded` will have their stale `queued`/`started` search rows automatically cleaned up on first startup.
- If you previously relied on the automatic setup-admin music data purge at startup, set `CURATORR_ENABLE_SETUP_ADMIN_MUSIC_CLEANUP=true` in your environment to restore that behaviour.
- No Plex, Lidarr, or media-server reconnection is required.
