# Curatorr v0.1.83

## Summary

- **Plex playlist artwork updates are now applied directly from Curatorr's stored files.** Instead of depending on Plex fetching a Curatorr-hosted artwork URL later, Curatorr now uploads the saved image bytes straight to Plex when it reapplies playlist artwork.
- **This hardens imported and generated playlists when Curatorr is temporarily offline.** In particular, it addresses the reported failure mode where opening some Spotify-imported playlists after a reboot could repeatedly destabilize Plex if Curatorr was not running.
- **Compatibility is preserved with a safe fallback path.** If a Plex server rejects the direct artwork upload, Curatorr still falls back to the existing URL-based artwork update flow rather than failing outright.

## Fixed

- Changed the Plex playlist artwork apply path to read stored playlist artwork from disk and `POST` the binary image directly to Plex's metadata artwork endpoint.
- Removed the normal dependency on Plex re-fetching a Curatorr-local `/api/music/playlists/artwork/...` URL after playlist sync, reducing offline sensitivity for stored playlist artwork.
- Kept the legacy `url=` artwork update request as a compatibility fallback when direct binary upload is not accepted by the target Plex build.
- Added focused regression coverage for both successful direct uploads and the fallback path so future playlist-artwork refactors keep the offline-safe behavior intact.

## Upgrade Notes

- No manual migration is required for this release.
- Existing playlists that use preserved or custom stored artwork will pick up the safer direct-upload behavior automatically the next time Curatorr reapplies artwork during a playlist sync or artwork change.
- This release does not change imported-playlist track matching behavior. Unmatched Spotify tracks are still stored separately for review and are not exported into Plex playlists.
