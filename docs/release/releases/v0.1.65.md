# Curatorr v0.1.65

## Summary

- **Random Library Mix is now a built-in smart-playlist starting point** — the wizard can create a 50-track daily random library sampler with one track per artist and one track per album, and the same random ordering / album cap controls are available to custom playlist rules.
- **Decade filtering now comes from Curatorr track metadata** — Decades are generated from track years and release dates, including `2020s`, and are shown separately from Last.fm Tags so decade-looking Last.fm tags no longer drive year filtering.
- **Startup and setup job behavior is less disruptive** — Curatorr starts scheduled job timers on container boot without immediately running every job, while server wizard completion starts the scheduler and records the initial master refresh through the normal Jobs UI.

## Fixed

- Added a `Random Library Mix` wizard template for 50 random tracks, daily rebuilds, one track per artist, and one track per album.
- Added `random` as a real playlist sort mode across personal, global, preview, and Settings playlist rule flows.
- Added `maxTracksPerAlbum` support so smart playlists can limit album repeats in previews and sync output.
- Added dedicated Decades filters to the playlist wizard, playlist edit flow, and global playlist settings, generated from track year and original release date metadata.
- Preserved track year and release-date data during master track refreshes from Plex, Jellyfin, and Emby library cache reads.
- Kept Last.fm tags separate from generated decade filters, preventing artist-level Last.fm tags such as `2000s` from matching every track by that artist.
- Fixed imported-playlist smart conversion so inferred and detected content can include generated Decades alongside genres, moods, and Last.fm tags.
- Fixed Last.fm sync/backfill rows with zero duration being replayed as skips during stats rebuilds when the original play event was recorded as a non-skip.
- Fixed container startup so scheduled jobs are registered without all firing immediately during boot.
- Fixed server wizard completion so the scheduler starts after setup and the initial master track refresh is recorded through `masterTrackRefresh` job status.
- Fixed Settings -> Jobs interval validation so the weekly Last.fm Tag Sync default of `10080` minutes can be saved without being rejected by the old one-day cap.
- Added `COOKIE_SECURE=true` support for forcing secure cookies in HTTPS/proxy deployments.

## Upgrade Notes

- Recreate the app container after pulling `mickygx/curatorr:latest`.
- Run or wait for **Master Track Refresh** after upgrading if the Decades section is empty; decade pills are generated from track year/release-date data stored in the refreshed master cache.
- Hard refresh the browser after upgrading. This release changes playlist wizard and Settings playlist-builder JavaScript.
- Last.fm Tags may still contain labels such as `2000s` if Last.fm provides them. Use the new Decades section for track-year filtering.
