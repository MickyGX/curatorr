# Curatorr v0.1.67

## Summary

- **Admin Users counts are now based on real per-user totals instead of mixed identities** — playlist and Lidarr usage stats aggregate across a Plex user's known aliases, so rows like `Toby Blenkinsop` no longer miss data stored under a normalized username.
- **Playlist totals on Admin Users now reflect the same model as the Playlists page** — synced system, user, and linked playlists are counted once, and unsynced drafts are shown separately instead of being folded into the live total.
- **Lidarr album adds now record track totals more reliably** — when Lidarr omits `trackCount` on the initial album payload, Curatorr falls back to the album details and then the album track list so future Admin Users track counts can populate correctly.

## Fixed

- Fixed Admin Users playlist totals so synced personal playlists are no longer double-counted on top of generated totals.
- Fixed Admin Users playlist aggregation to include identity aliases for the same Plex user, matching the existing Playlists page behavior.
- Updated the Admin Users playlist column copy and sorting data to reflect `system`, `user`, and `other` playlist counts, with unsynced drafts shown as a separate note.
- Fixed Admin Users Lidarr stats so they are sourced from `lidarr_usage` only, avoiding false artist/album counts coming from placeholder progress rows for already-monitored items.
- Fixed false positive Lidarr totals for users such as `lisal96` and `spider3001` whose historical progress rows represented already-present Lidarr content rather than Curatorr-triggered adds.
- Added a Lidarr album track-count fallback path that checks the live album payload and then the album track list when `statistics.trackCount` is missing.
- Updated both manual and automatic Lidarr album-add flows to record `tracks` usage with the resolved fallback count.
- Added tests covering alias-based Lidarr aggregation and the album-track fallback path.

## Upgrade Notes

- Recreate the app container after pulling `mickygx/curatorr:latest`.
- Hard refresh the browser after upgrading. This release changes the Admin Users page rendering and sort metadata.
- Historical Lidarr track totals are not backfilled by this release. The `tracks` column will populate for future album adds recorded after upgrading.
