# Curatorr v0.1.86

## Summary

- **Smart playlist wizard name and artwork state fixes.** The summary name in Step 5 now reflects every keystroke in real time instead of requiring a back/forward step to refresh. The custom artwork section now shows a thumbnail of the current stored image (edit mode) or the pending upload (after back-navigation), with updated status wording that makes it explicit the image will be applied on save.
- **Imported playlist source link.** The imported playlist edit modal now surfaces a direct link back to the original Spotify or YouTube playlist when the source reference is available.
- **Starfield and page-layout housekeeping.** `starfield-3d.js` is now loaded from the shared `<head>` partial so the background effect is consistent on all pages. Panel header and body styles have been refactored to scoped `dash-content--<page>` CSS classes across seven pages, removing old body-level class dependencies.
- **Diagnostics improvements.** Playlist rebuild errors and Plex add-items HTTP failures now write structured log entries, making it easier to diagnose sync problems from the log viewer.

## Fixed

- Smart playlist wizard Step 5: typing in the playlist name field now updates the summary row below it immediately; previously the summary only refreshed after navigating away and back.
- Smart playlist wizard Step 5: a thumbnail image now appears below the file picker showing the currently saved artwork (when editing an existing playlist) or the pending upload (when navigating back to the step mid-creation). The status text was updated from "New custom image selected." to "New custom image ready — will be applied on save." to make the persisted state unambiguous.
- Smart playlist wizard Step 5: the thumbnail tracks file picker changes live — selecting a new file updates the preview; clearing the selection restores the saved-asset thumbnail or removes it if none exists.
- Imported playlist edit modal: a "Source" row now appears with a clickable link to the original Spotify or YouTube playlist when `sourceRef` is present on the playlist card. The link label reads "View on Spotify" or "View on YouTube" accordingly.
- Lidarr artist add: `monitorNewItems` was hardcoded to `"none"` in the add payload regardless of the configured new-artist monitoring mode. It now correctly reflects the configured `newArtistMonitoringMode` setting, consistent with `addOptions.monitor`.
- Imported playlist smart-conversion: the genre/tag inference endpoint no longer uses the stale in-memory master-tracks cache; it now queries only the playlist's matched tracks directly, fixing a race condition where newly synced tracks were invisible to the prefill logic. The playlist create endpoint now accepts the conversion even when the library currently has zero matching tracks (saves as a draft), and allows the source imported playlist to be removed in the same request regardless of the track count.
- `starfield-3d.js` was previously included as an inline `<script>` tag in each individual view, resulting in the script sometimes being absent. It is now loaded once from `partials/head.ejs` with `defer` and removed from the per-page script lists.
- Per-page panel styles (Artists, Blend, Playlists, Tracks, History, Discover, Admin Users, Settings) were previously scoped via body-level CSS classes (`cur-playlists-page`, `cur-artists-page`, etc.). These have been refactored to `dash-content--<page>` modifier classes on the content element, bringing them in line with the pattern used on newer pages.
- History table column header (`.cur-hi-head`) is no longer `position: sticky` — it now scrolls with the table body rather than floating over content. The redundant `background` gradient on the header was also removed.
- Listening Report profile hero: section height increased to `264px` and top padding adjusted to `170px` for better visual balance. Stat values are now `24px` with tighter letter-spacing; stat labels are `10px`. Mobile breakpoint now applies correctly at ≤600px with a slightly smaller avatar and adjusted `padding-top`.
- Playlist rebuild endpoint (`POST /api/music/playlists/*/rebuild`) now emits a structured error log entry before returning HTTP 500, making rebuild failures visible in the log viewer.
- Plex add-items operation (`replacePlexPlaylistItems`) now logs the full HTTP status and response body (capped to 500 characters) when Plex returns a non-OK response, replacing the previously silent failure path.
- Spotify integration docs updated with explicit Spotify Premium requirements: private/owned playlist imports require Premium on the connecting user's account; the Developer App owner's account must also have an active Premium subscription when the app is in Development mode.

## Upgrade Notes

- No database migration required.
- No environment variable changes required.
- No Plex, Jellyfin, or Emby reconnection required.
