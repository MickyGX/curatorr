# Curatorr v0.1.97

## Summary

- **M3U imports can now be refreshed.** Curatorr stores the uploaded `.m3u` or `.m3u8` source on import, then reuses that stored source when you choose **Refresh import** from the Playlists page.
- **Imported M3U playlist sync is safer.** Refresh keeps source ordering intact, updates missing-track counts as the local library changes, and replaces the Plex playlist with the latest matched track list.
- **Tautulli Gap-Fill uses the expected date filter.** History repair requests now send `after` as `YYYY-MM-DD` instead of Unix seconds.

## Fixed

- Fixed M3U/M3U8 imports being one-shot only. New imports now persist the uploaded source text and filename in `user_generated_playlists`.
- Fixed `/api/music/playlists/imported-refresh` rejecting `m3u-file` playlists even when Curatorr had enough information to rebuild them.
- Fixed the Playlists page action menu so M3U imported playlists show **Refresh import** rather than falling back to the generic rebuild label.
- Fixed Tautulli Gap-Fill requests so the `after` parameter matches Tautulli's date-style API filter.
- Added route-level regression coverage for M3U import and refresh through the real HTTP endpoints with Plex playlist creation, replacement, verification, and stored source metadata mocked at the boundary.

## Upgrade Notes

- No manual migration is required. Curatorr adds the new stored M3U source columns automatically on startup.
- Existing M3U imports created before this release do not have uploaded source text stored, so they should be re-imported once before **Refresh import** can work for them.
- Rebuild or redeploy Curatorr to pick up the stored M3U refresh route, Playlists UI action, and Tautulli Gap-Fill API fix.
