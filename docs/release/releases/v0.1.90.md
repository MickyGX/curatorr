# Curatorr v0.1.90

## Summary

- **Scheduled rebuilds now handle setup-admin id collisions.** If the Plex owner/admin has the same id as the local setup-admin account, Smart Playlist Sync and Rotating Playlist Sync now keep that real media-server owner in scheduler discovery when Curatorr has a stored per-user Plex token.
- **Setup-only accounts stay protected.** The scheduler still excludes true setup-only local accounts, so the recovery/admin identity does not create or update personal music playlists.
- **Regression coverage added.** The scheduler discovery tests now cover the same-name setup-admin/Plex-owner case that could make jobs complete in milliseconds without rebuilding playlists.

## Fixed

- Smart Playlist Sync no longer drops a same-name Plex owner/admin just because the id also matches the setup-admin identity.
- Rotating Playlist Sync now uses the same collision-aware playlist scheduler discovery, covering Daily Mix and the built-in Curatorr rotating playlist.
- Setup-only local accounts without a per-user Plex token remain excluded from scheduled playlist work.

## Upgrade Notes

- No database migration required.
- No environment variable changes required.
- After upgrading, check **Settings -> Jobs** for the next Smart Playlist Sync or Rotating Playlist Sync run. A previously skipped owner should now produce normal playlist build/sync log entries instead of a near-instant no-op success.
