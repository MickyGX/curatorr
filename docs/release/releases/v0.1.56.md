# Curatorr v0.1.56

## Summary

- **Playlist track images now load near-instantly on repeat visits** — the art proxy now caches up to 500 album and artist thumbnails in memory for one hour, eliminating a fresh Plex (or Jellyfin/Emby) HTTP round-trip for every image on the page.
- **Faster container restarts on large libraries** — two startup migration queries that performed full table scans on every restart are now skipped when no rows need updating.
- **Version check no longer hangs on poor connectivity** — the Docker Hub latest-release lookup is now capped at 8 seconds.

## Fixed

- Added server-side LRU-style in-memory cache (max 500 entries, 1-hour TTL) to `/api/plex/art` and `/api/ms/art`. Previously every track thumbnail on the playlist page triggered a fresh upstream fetch per browser request — with 100 tracks that was ~200 concurrent Plex connections. The browser `Cache-Control` header already handled repeat page loads; this fixes within-session and first-load concurrency.
- Two `UPDATE` statements in `initDb` (`track_enrichment.updated_at` and `open_sessions.last_event_at`) previously ran a full table scan on every container start. They are now guarded by a `SELECT 1 ... LIMIT 1` existence check and skipped when nothing needs migrating.
- `fetchLatestDockerTag` now passes `AbortSignal.timeout(8000)` to the Docker Hub fetch so the `/api/version` endpoint returns promptly even when the NAS has slow or no outbound internet access.

## Upgrade Notes

- No app configuration changes are required.
- Recreate the app container after pulling `mickygx/curatorr:latest`.
- The art cache is in-memory and resets on container restart — images will be re-fetched once from Plex on the first load after a restart, then served from cache for the rest of the session.
