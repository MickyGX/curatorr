# Curatorr v0.1.74

## Summary

- **Artist suggestions handle collaboration credits more accurately** with broader detection for joint credits already present in the library, including comma-separated primary-artist-plus-guests patterns and person-name collaborations stored under a combined artist name.
- **Recommendation noise is lower** because temporary collaboration credits are less likely to appear as standalone discovery candidates in both library-derived and Last.fm-derived artist suggestion pools.
- **Band-name false positives are reduced** so real act names like `Earth, Wind & Fire` and `Southside Johnny & The Asbury Jukes` are less likely to be filtered out as collaborations.

## Fixed

- Expanded the collaboration-credit heuristic to split artist names on both commas and ampersands when evaluating whether a suggestion is really a joint credit.
- Fixed cases where joint artists already present in the library under the combined artist name could still reappear as standalone discovery candidates.
- Added a primary-artist-plus-guests detection path so credits like `Artist A, Guest B & Guest C` can be recognised when the joint name is already in the user's library.
- Preserved the existing guardrails against false positives by requiring stronger library evidence before suppressing named acts that are not ad-hoc collaborations.
- Improved person-name collaboration detection so combined-name library credits are filtered more reliably without catching band names that start with articles like `The`.
- Applied the refined collaboration-credit logic consistently across both library-derived and Last.fm-derived recommendation candidates.

## Upgrade Notes

- No manual migration is required for this release.
- Artist suggestions will reflect the tighter collaboration-credit filtering the next time Curatorr rebuilds or refreshes discovery recommendations.
- If you previously saw joint credits show up as standalone artist suggestions, those entries should drop out after the next recommendation refresh cycle.
