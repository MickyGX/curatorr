# Curatorr v0.1.105

## Summary

This release adds playlist backup and restore. Curatorr can save every playlist it manages to a file and rebuild those playlists later, on the same server or a new one. It can also keep copies of Plex playlists it doesn't manage. Playlists now survive a Plex database rebuild or reinstall instead of losing their tracks.

## Added

- **Playlist backup files**: **Playlists → Back up and restore playlists → Export** downloads a `.curatorr.json` backup. It saves smart playlist rules, global playlists (admins), imported and static track lists with their missing tracks, system playlist names and artwork, and optionally each user's system playlist settings. Artwork can be left out for a smaller file. Admins can include every user's playlists. Passwords, tokens, and API keys are never exported.
- **Per-playlist export**: each playlist card has **Export backup** and **Export M3U**, and selected cards can be exported together with **Export Selected**.
- **Restore**: the **Restore** tab previews a backup before anything changes, showing how many tracks were found in the current library. Smart playlists rebuild from their rules. Imported and static playlists are matched by file path, MusicBrainz ID, or artist, title, and album, and unmatched tracks go to the playlist's missing list. You choose whether to rename or skip playlists whose names are taken. Admins can restore other users' playlists to their original owners.
- **Plex playlist backups**: the **Plex playlists** tab saves copies of Plex playlists that Curatorr doesn't manage, such as playlists made in Plexamp, without adding a second copy to Plex. Backups refresh weekly while the Plex playlist exists, and **Restore to Plex** on the card recreates a lost playlist.
- New wiki page: **Playlist Backup and Restore**, including steps for rebuilding playlists after a new Plex install.

## Fixed

- Fixed a master track cache refresh deleting playlist tracks whose Plex IDs had changed, for example after a Plex database rebuild or reinstall. Curatorr now stores each playlist track's identity and re-matches it to the new ID. Imported and static playlists then re-sync automatically. A track is moved to the missing list only when Plex or the library refresh confirms it is gone. Tracks from libraries Curatorr doesn't cache are left unchanged.
- Fixed **Refresh import** failing with "Original Plex source could not be resolved" when an imported Plex playlist or collection no longer exists. Refresh now rebuilds from Curatorr's stored tracks and moves newly found tracks back from the missing list. Plex sources are also checked by title, so a different playlist that reuses the old ID on a new server is never read.
- Importing a Plex playlist that is already saved as a backup now adds it to Plex instead of leaving it backup-only.
- Added regression tests for track re-matching, backup export and restore across a re-keyed library, Plex playlist backups, and refreshing from stored tracks.

## Upgrade Notes

- Update the Curatorr app image and recreate the container as usual. No analyzer update is required.
- New columns are added to the database automatically on startup, and existing playlist tracks are filled in from the library cache. The next **Master Track Cache Refresh** re-matches any playlist tracks whose IDs have changed.
- Restores accept backup files up to 64 MB by default. Set `PLAYLIST_BACKUP_BODY_LIMIT` (for example `128mb`) for larger backups with a lot of embedded artwork.
- Backup files contain usernames, playlist names, and file paths, so store them privately.
- Details: `docs/wiki/Playlist-Backup.md`.
