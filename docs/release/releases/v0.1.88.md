# Curatorr v0.1.88

## Summary

- **Scheduler reliability on restart-prone setups.** Background jobs whose interval is longer than the time between container restarts (e.g. the 24-hour Rotating Playlist Sync that builds your Daily Mix and Curatorr playlists, the Tautulli Gap-Fill Sync, and the weekly Last.fm Tag Sync) could be starved forever — the timer reset to zero on every restart and never reached its interval. Curatorr now runs any overdue job on a short, staggered catch-up after startup, so missed work recovers on its own.
- **Responsive UI during rebuilds.** A Smart Playlist Sync over a large library no longer makes the app unresponsive. The job yields to the event loop between playlist builds, so the web UI and container healthchecks keep answering while a rebuild is in progress.
- **Playlist created date.** The playlist detail panel now shows when a playlist was created, alongside the existing last-updated date.
- **Prefer artist-folder copies over compilations.** A new smart playlist filter that drops the compilation / "Various Artists" copy of a recording whenever the same track also exists in a normal artist folder.

## Fixed

- Added boot catch-up to the job scheduler: on startup, any enabled job whose last run is older than its interval is run on a staggered delay (2-minute initial delay, then spaced out) instead of waiting a full interval from boot. This prevents long-interval jobs from being starved by frequent restarts.
- Smart Playlist Sync now `await`s an event-loop yield after each playlist build, keeping the HTTP server (including the `/healthz` endpoint) responsive during heavy synchronous work.
- The playlist detail panel surfaces the stored `created_at` for generated, personal, and global playlists.
- Added the `preferArtistFolderOverCompilation` track filter:
  - Detects compilation tracks from "Various Artists"/"Compilations" album and folder naming.
  - Suppresses the compilation copy when a non-compilation (artist-folder) copy of the same recording exists, matched by recording MBID or by artist/title with a close duration.
  - Applies independently of the deduplicate toggles, so it works even when duplicate removal is otherwise off.
  - Exposed as a toggle in the smart playlist wizard and persisted through the settings and API track-filter handling.
- User-initiated playlist rebuilds now opt into surfacing errors (HTTP 500) instead of failing silently; background callers (webhooks, scheduler) remain fire-and-forget. Added error logging for failed Plex add-items requests.
- Added regression coverage for compilation-vs-artist-folder duplicate suppression.

## Upgrade Notes

- No database migration required. The created date uses the existing `created_at` columns; playlists created before that column existed will show the date the column was added rather than their true original creation date.
- No environment variable changes and no media-server reconnection required.
- The catch-up runs are staggered after a 2-minute warm-up delay, so a busy NAS is not slammed on startup.
- If you run a container **healthcheck plus a restart-on-unhealthy watcher** (deunhealth, Portainer, Synology Container Manager, Kubernetes liveness, etc.), point the healthcheck at the lightweight `/healthz` endpoint and allow a generous number of retries. Combined with the responsiveness fix above, this prevents a long rebuild from being misread as "unhealthy" and restarted mid-run.
