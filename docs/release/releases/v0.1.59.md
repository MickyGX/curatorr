# Curatorr v0.1.59

## Summary

- **Cold-start and first-load performance improved substantially** — Curatorr now sequentially pre-reads the SQLite database before opening it, starts accepting HTTP connections before heavyweight background jobs begin, keeps the WAL smaller with a lower auto-checkpoint threshold, and truncates the WAL during graceful shutdown. Together these changes remove the long startup stall where the app could appear unavailable or sluggish on NAS hardware.
- **Immediate startup playlist churn reduced** — startup no longer immediately runs the heaviest background jobs such as master-track refresh and smart-playlist sync before the server is reachable. This directly addresses the lag where playlist rebuilding and other synchronous work could delay first access to the app.
- **Saved smart-playlist templates completed** — saved templates now persist advanced track filters and their originating starting point, appear as reusable choices at the top of Step 1, and support overwrite/delete management on the finish step so playlists can be branched cleanly from an existing ruleset.
- **Playlist page header polish** — the rebuilding status indicator now sits to the left of the playlist action buttons, making the state easier to notice without pushing the controls around awkwardly.

## Fixed

- `start()` now pre-warms the NAS page cache with a sequential read of `curatorr.db` before `initDb()` opens SQLite. On cold storage this avoids the 60-90 second random-read penalty seen during database initialisation.
- Background jobs now start only after the Express server is already listening, and the immediate startup run skips `masterTrackRefresh` and `smartPlaylistSync`. This prevents the event loop from being blocked by expensive synchronous queries before the app is reachable.
- SQLite startup/shutdown behaviour was tuned for NAS installs: `wal_autocheckpoint` is reduced to 200 pages to keep the WAL small, and shutdown now runs `wal_checkpoint(TRUNCATE)` so the next startup does not inherit a bloated WAL file.
- `docker-entrypoint.sh` no longer recursively `chown`s entire data/config trees on every boot. It now only fixes paths whose owner is actually wrong, which reduces unnecessary I/O and startup delay on larger installs.
- Saved playlist templates now store a structured payload containing `rules`, `trackFilters`, and `startingPointId`, while staying backward-compatible with older template rows that only stored rules.
- Added `PUT /api/music/playlist-templates/:id`, completing the saved-template lifecycle so users can update an existing template instead of creating a new one every time.
- The smart-playlist wizard now distinguishes between a selected saved template and its base starting point. Selecting a saved template loads the full saved state, highlights the recorded base starter, and still allows the user to change the starter before creating a branched playlist.
- Template saves from the wizard now include advanced track filters as well as the main rules, so reusing a saved template actually recreates the full intended starting state.
- The playlists page header status text was moved to the left of the action buttons so rebuild feedback remains visible while keeping the controls aligned.

## Upgrade Notes

- Recreate the app container after pulling `mickygx/curatorr:latest`.
- Existing saved templates created before `v0.1.59` do not contain `startingPointId`. They remain usable, but will default to `Custom` as their base starter until they are saved or updated once in the new wizard.
- If you maintain your own Compose file, review the updated analyzer limits and proxy/webhook environment examples in `docker-compose.yml` before merging local changes.
